# Data Model: Command Callback Persistence

## Entity: Command

Durable record for one asynchronous command and its callback audit trail.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `id` | uuid string | Yes | Unique command identifier generated by the system |
| `type` | string | Yes | Command type used to resolve a processing pipeline |
| `payload` | object | Yes | Original payload received during submission |
| `external_id` | string or null | No | Business object identifier from the source system |
| `callback` | string or null | No | Callback URL supplied by the source system |
| `status` | enum | Yes | Command processing status |
| `response_payload` | object or null | No | Processing response when command succeeds |
| `error_message` | string or null | No | Processing error when command fails |
| `callback_status` | enum | Yes | Callback delivery status |
| `callback_error_message` | string or null | No | Callback delivery error when delivery fails |
| `retry_count` | integer | Yes | Number of callback delivery attempts recorded by the system |
| `request_received_at` | datetime | Yes | Timestamp when command was accepted |
| `processing_started_at` | datetime or null | No | Timestamp when worker processing started |
| `processing_finished_at` | datetime or null | No | Timestamp when processing completed or failed |
| `callback_sent_at` | datetime or null | No | Timestamp when callback delivery succeeded |

## Entity: CommandStatus

Allowed command processing states.

```text
queued
processing
completed
failed
```

## Entity: CallbackStatus

Allowed callback delivery states.

```text
not_required
pending
sent
failed
```

## Entity: Callback Delivery

Audit record represented on the command for a callback attempt.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `callback_status` | enum | Yes | Delivery result state |
| `callback_error_message` | string or null | No | Delivery failure reason |
| `callback_sent_at` | datetime or null | No | Successful delivery timestamp |
| `retry_count` | integer | Yes | Number of delivery attempts |

## Validation Rules

- `type` must be present and non-blank.
- `payload` must be present and be an object.
- `external_id` is optional and may repeat across commands.
- `callback` is optional; missing, null, and blank values mean no callback is required.
- `callback_status` is `pending` only when callback is present and non-blank.
- `callback_status` is `not_required` when callback is missing, null, or blank.
- `response_payload` is stored only for successful processing when a result exists.
- `error_message` is stored when processing fails.
- `callback_error_message` is stored when callback delivery fails.
- Callback delivery failure must not change `status`.
- Command records are retained after final processing status.

## State Transitions

Command processing:

```text
queued -> processing -> completed
queued -> processing -> failed
```

Callback delivery:

```text
not_required
pending -> sent
pending -> failed
```

## Relationships

- A Command may have zero or one callback URL.
- A Command may be queried by command id.
- A Command may be queried by external id, where multiple commands may share the same external id.
- A Command type maps to one processing pipeline through the handler registry.
